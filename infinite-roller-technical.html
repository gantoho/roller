2. requestAnimationFrame 引擎

2.1 核心原理

每帧由 JS 回调计算偏移量，通过 transform: translate3d() 写入 DOM，利用取模运算实现无限循环。

时间轴 ──────────────────────────────────────────────────▶ 帧 N: offset += speed × deltaT 取模: effective = offset % originalSize 写入: track.style.transform = translate3d(-effective, 0, 0) 帧 N+1: offset += speed × deltaT 取模: effective = offset % originalSize 写入: track.style.transform = translate3d(-effective, 0, 0) 帧 N+2: ...（持续循环，offset 单调递增永不清零）

2.2 关键实现细节

  • 时间差驱动：step = speed × (now - lastTimestamp) / 1000，与帧率无关，60fps 和 120fps 下速度一致
  • 单帧步长限制（stepMaxRatio）：切后台恢复后帧间隔可能很大，限制单帧步长不超过 originalSize × 0.5，防止视觉跳跃
  • 精度保护（precisionThreshold）：offset 超过 1e8 时主动取模，防止浮点精度丢失
  • 取模映射：effectiveOffset = offset % originalSize，将单调递增的 offset 映射到 [0, originalSize) 区间，配合克隆副本保证视觉连续

2.3 线程模型

JS 回调主线程 — 每帧执行一次
样式计算 + 布局主线程 — 每次 DOM 写入触发
合成 (Composite)合成器线程 — transform 仅触发合成，不触发重排/重绘

2.4 优缺点

  • 优点：逐帧精确控制、速度变化即时生效、页面不可见时自动暂停（rAF 行为）
  • 缺点：主线程每帧参与 JS 执行 + 样式计算，高负载时可能掉帧

3. CSS Transition 引擎

3.1 核心原理

每个周期：设置 transition: transform Ns linear 一次性滑到终点，完成后 snap 回 0 并立即开始下一周期。

周期 1: track.style.transition = 'transform 2s linear' track.style.transform = translate3d(-originalSize, 0, 0) ──── 2s 后 ────▶ track.style.transition = 'none' ← snap（无过渡） track.style.transform = translate3d(0, 0, 0) void track.offsetHeight ← 强制重排 周期 2: track.style.transition = 'transform 2s linear' track.style.transform = translate3d(-originalSize, 0, 0) ...

3.2 关键实现细节

  • 周期控制：setTimeout(fn, duration * 1000) 精确匹配 transition 完成时间，在 transitionend 之前执行 snap
  • 暂停实现：读取 getComputedStyle().transform 获取当前偏移 → transition: none 冻结 → 计算剩余时间比例
  • 恢复实现：从冻结位置以剩余时间启动新的 transition
  • 强制重排：snap 后 void track.offsetHeight 确保浏览器在下一帧识别到 transform 归零，否则 transition 不会重新触发

3.3 线程模型

JS 回调主线程 — 仅周期边界（snap 时）
动画执行合成器线程 — transition 期间的每一帧
样式计算主线程 — 仅 snap 时

3.4 优缺点

  • 优点：动画期间主线程零开销，合成器线程独立驱动，流畅度最高
  • 缺点：暂停/恢复需手动计算剩余时间；速度变化需重新计算 duration；页面不可见时仍继续运行（但 setTimeout 节流）；snap 瞬间有 1 帧可能闪烁

4. CSS Animation 引擎

4.1 核心原理

动态创建 @keyframes 规则，设置 animation: NAME Ds linear infinite，由浏览器合成器线程自动循环。

动态生成 <style>: @keyframes roller-anim-xxx { 0% { transform: translate3d(0, 0, 0); } 100% { transform: translate3d(-${originalSize}px, 0, 0); } } 应用: track.style.animation = 'roller-anim-xxx 2s linear infinite' 暂停: track.style.animationPlayState = 'paused' 恢复: track.style.animationPlayState = 'running'

4.2 关键实现细节

  • @keyframes 动态生成：每次 originalSize 或 speed 变化时，移除旧 <style> 标签，创建新的 @keyframes 规则
  • 暂停/恢复：直接切换 animationPlayState，天然支持立即冻结，无需手动计算位置
  • 无限循环：animation: ... infinite 由浏览器自动处理，不存在 setTimeout 精度问题
  • 刷新时重建：animation: none → void offsetHeight → 新 animation，确保从 0 位置重新开始

4.3 线程模型

JS 回调主线程 — 仅 @keyframes 创建/销毁时
动画执行合成器线程 — 每一帧（包括循环）
样式计算无 — 合成器线程直接驱动

4.4 优缺点

  • 优点：完全声明式，主线程几乎零参与；暂停/恢复最简单；infinite 循环由浏览器内部处理，无 setTimeout 精度问题
  • 缺点：速度变化需替换 @keyframes（操作 DOM <style>）；页面不可见时仍继续运行；无法获取当前动画进度（API 限制）

6. 性能优化通用策略

6.1 transform3d 硬件加速

三种引擎统一使用 transform: translate3d(x, 0, 0) 而非 translateX()，强制 GPU 合成层，避免触发 Layout/Paint。

6.2 will-change + backface-visibility

track.style.willChange = 'transform';
track.style.backfaceVisibility = 'hidden';
track.style.flexShrink = '0';
  • will-change: transform — 提前通知浏览器创建独立合成层
  • backface-visibility: hidden — 减少不必要的背面渲染
  • flex-shrink: 0 — 防止 flex 容器压缩轨道高度

6.3 margin 替代 gap

CSS gap 属性在克隆组边界处会产生间距突变（克隆组最后一项与下一组第一项之间无 gap），因此使用独立 margin 确保每项间距一致。

6.4 ResizeObserver + 防抖

同时使用 ResizeObserver（容器尺寸变化）和 window.resize（作为兜底），通过 resizeDebounceMs（默认 100ms）防抖避免频繁重建。

6.5 克隆策略

轨道总长至少为 originalSize × minCloneMultiplier（默认 3 倍）。当内容不足容器时（contentInsufficient: 'scroll'），额外克隆使轨道超过 originalSize + containerSize × 1.8，确保滚动时视口内始终有内容。
